## 1. 제작 방식 (가장 중요)
영상에 들어가는 모든 것은 아래 세 가지 중 하나로만 만든다. 각 항목이 어느 방식인지는 `REGISTRY.md`의 `방식` 열에 정해져 있다.

| 방식 | 대상 | 만드는 방법 |
|---|---|---|
| **3D** | 지도, 지형, 바다, 루트 선, 장소 핀, 지도 위를 움직이는 단순한 탈것 토큰, 사진 액자, 정보 패널 | **ChatGPT는 설계도(치수표)와 참고 이미지까지만** 만든다. 모델링(스크립트 실행, `.blend`·`.glb`)은 **Claude**가 한다 (4-1) |
| **실제 사진** | 관광지·장소, 음식, 실제 교통수단(KTX, 부산 시내버스, 해변열차, 스카이캡슐 등), 버스정류장. 실제로 존재하는 대상은 모두 해당 | 사용권이 확인된 실제 사진을 찾아 쓴다. **AI로 만들거나 합성·변형하지 않는다** |
| **일러스트** | 실제로 존재하지 않거나 특정 실물이 아닌 것: 여행자 캐릭터, 아이콘, 타이틀·자막 배경 | AI 이미지 생성 가능. 단, 누가 봐도 그림인 평면 일러스트 스타일만 쓴다 |

판단이 애매하면 이렇게 정한다.
- 시청자가 "실제 부산의 모습"으로 받아들일 수 있으면 → **실제 사진**
- 장식·안내용 그림이면 → **일러스트**
- 그래도 애매하면 사용자에게 묻는다.

## 2. 실제 사진 규칙
### 2-1. 어디서 구하나 (위에서부터 우선)
1. **사용자 본인이 찍은 사진.** 사용자가 제공하면 가장 먼저 쓴다.
2. **공공누리 사진:** 한국관광공사 포토코리아, 비짓부산, 부산시, 각 구청 등 공공기관 자료. 제1유형(출처표시)이 가장 좋다.
3. **CC0 / CC BY / CC BY-SA 사진:** 위키미디어 공용 등.
4. **사진별 라이선스가 명시된 무료 사진 사이트.** 라이선스 조건을 그대로 기록한다.

### 2-2. 쓰면 안 되는 사진
- 블로그, SNS, 검색 결과, 뉴스 기사 사진처럼 사용권이 불명확한 사진
- 워터마크가 있는 사진 (워터마크를 지우는 것도 금지)
- AI가 만들었거나 합성된 사진, 출처를 알 수 없는 사진

### 2-3. 라이선스 조건 (영상이 수익화될 수 있다고 보고 기본값을 정한다)
| 조건 | 기본 처리 |
|---|---|
| 상업적 이용 금지 (공공누리 2·4유형, CC BY-NC 등) | **쓰지 않는다.** 사용자가 "수익화 안 함"이라고 확인하면 쓸 수 있다 |
| 변경 금지 (공공누리 3·4유형, CC BY-ND 등) | 자르기·색 보정도 하지 않는다. 원본 비율 그대로 여백을 두고 넣는다 |
| 출처 표시 | 사진 아래 작은 글씨 또는 엔딩 크레딧에 표시. 문구는 `CREDITS.md`에 기록 |

### 2-4. 허용되는 편집과 금지되는 편집
| 허용 (편집 기록에 남긴다) | 금지 |
|---|---|
| 자르기, 크기 조절 | 사물 추가·삭제, 생성형 채우기, 배경·하늘 바꾸기 |
| 밝기·대비·화이트밸런스의 가벼운 보정 | AI 업스케일처럼 없는 디테일을 만들어 내는 처리 |
| 사생활 보호용 얼굴·차량번호 흐림 | 스타일 필터, 그림처럼 바꾸기, 여러 사진 합성 |
| 영상에서의 천천히 확대·이동 (켄 번스 효과) | 다른 장소 사진을 그 장소인 것처럼 쓰기 |

### 2-5. 사진이 진짜 그 대상인지 확인하기
사진마다 아래를 확인해 사진 기록(`photo_sheet.md`)에 적는다.
1. **출처 확인:** 출처 페이지의 제목·설명에 그 장소 이름이 있는가.
2. **대조 확인:** 사진 속 특징이 `FACTS.md`의 사실과 맞는가.
3. **시기 확인:** 촬영 시기가 현재 모습과 맞는가. 아래가 주의할 예다.
   - **다릿돌전망대:** 2024년 확장 전 사진은 일자형이다. 현재는 U자형 191 m라서 확장 후 사진을 써야 한다.
   - **부산 시내버스:** 도색이 바뀌는 중이라 옛 도색과 새 도색이 섞여 있다. 어느 쪽인지 적는다.
4. **자막 정직성:** 자막이 사진보다 많이 말하면 안 된다.
   - 예: 사진 속 버스가 1001번이면 자막에 "1003번"이라고 쓰지 않는다. "부산 급행버스"처럼 사실에 맞게 쓴다.
   - 음식 사진이 그 식당 사진이 아니면 "부산 밀면"처럼 음식 이름만 쓴다.

### 2-6. 영상에 넣는 방법
- **기본: 편집 프로그램에서 합성한다.** Blender 렌더 결과 위에 편집 단계에서 사진을 올린다. 3D 조명과 색 변환이 사진 색을 바꾸지 않게 하기 위해서다.
- **3D 장면 안에 넣을 때:** 사진 액자(MAP05)의 사진 면은 Emission 셰이더(강도 1)로 하고, Blender 색 관리(View Transform)를 `Standard`로 둔다.

### 2-7. 저장소에 올릴 때
- 사용권이 재배포를 허용하는 사진만 사진 파일을 올린다: 본인 사진, 공공누리 1유형, CC0, CC BY, CC BY-SA.
- 재배포가 불명확한 사진은 파일을 올리지 않고 출처 링크만 기록한다. 이 저장소는 공개 저장소다.
- 사진 파일을 직접 내려받을 수 없으면 출처 링크를 기록하고 사용자에게 내려받아 달라고 요청한다. 비슷한 사진을 직접 만들어 대신 넣지 않는다.

## 3. 일러스트 규칙
- 실제 장소·음식·교통수단을 사실적으로 그리지 않는다. 버스 아이콘처럼 단순한 픽토그램은 괜찮다.
- 스타일은 평면 일러스트로 한다. 부드러운 선과 팔레트 색만 쓰고 사진처럼 보이는 질감은 쓰지 않는다.
- 실제 인물, 실제 브랜드 로고, 실제 앱 화면을 따라 그리지 않는다.
- `CREDITS.md`에 "AI 생성 일러스트"로 기록하고, 어떤 도구로 언제 만들었는지 적는다.

## 4. 3D 규칙
### 4-1. 역할 분담 (중요)
| 항목 | ChatGPT가 할 일 | Claude가 할 일 |
|---|---|---|
| MAP01~03 지도·지형·루트·핀 | 없음 (실제 고도·좌표 자료로 만들므로 설계도가 필요 없음) | 완료. 현재 `검토` 상태 |
| MAP04~06 탈것 토큰·사진 액자·정보 패널 | `SPEC_TEMPLATE.md` 설계도 + 참고 이미지 | 설계도 숫자대로 모델링 → 미리보기 렌더로 확인 → `.blend`·`.glb` 저장 |
| MAP07~08 카메라 경로·조명 | 연출 의도 문서: 샷 목록, 샷 길이(초), 카메라가 보여줄 곳, 시간대 | Blender에서 실제 카메라·조명 설정 |

ChatGPT가 지킬 것:
1. `blockout.py`, `map_build.py`, `.blend`, `.glb`는 만들지 않는다. 템플릿 스크립트도 실행하거나 고치지 않는다.
2. 설계도에는 Claude가 그대로 모델링할 수 있게 모든 치수·위치·색(hex)·움직임 값을 숫자로 적는다. 애매한 값은 13번 섹션에 적는다.
3. 참고 이미지는 모양·색 참고용이다. 치수 기준은 설계도 숫자다. 토큰·액자·패널은 실물이 아니므로 AI 이미지로 만들어도 된다.
4. 설계도를 저장하면 `REGISTRY.md` 상태를 `설계도`로 바꾸고, 사용자에게 이렇게 알린다: "Claude에게 모델링 요청: `busan-3d/assets/{ID}_{영문명}/spec.md`"
5. Claude가 만든 결과(`previews/`, `validation.md`)를 보고 수정할 점이 있으면 설계도 버전을 올려 고친다. 모델 파일은 직접 고치지 않는다.

### 4-2. 기술 규칙
| 항목 | 규칙 |
|---|---|
| 툴 | Blender 4.2 LTS 이상 |
| 축 | Z가 위, +Y가 북쪽, +X가 동쪽 |
| 지도 축척 | `map_template.py` 기본값 1 unit = 10 km, 높이 3배 과장 [설정] |
| 일반 소품 단위 | 1 unit = 1 m. 정면은 -Y, 원점은 바닥 중앙 |
| 오브젝트 이름 | `{ID}_{영문명}_{부품}_L0` 예) `MAP04_TransitTokens_BusBody_L0` |
| 재질 이름 | `M_{영문명}_{재질}` |
| 지도 좌표 | `FACTS.md` 4장(OpenStreetMap 확인 좌표)만 쓴다. 좌표가 없는 장소는 OpenStreetMap에서 찾아 출처(노드·웨이 번호)와 함께 추가하고 사용자에게 확인받는다. 좌표를 추측하지 않는다 |
| 지형 높이 | SRTM이나 Copernicus DEM 같은 공개 고도 자료로 높이 이미지(PNG)를 만든다. 자료 이름과 요구하는 출처 표기 문구를 `CREDITS.md`에 적는다 |
| 지도 출처 표기 | OpenStreetMap 좌표를 쓰므로 "© OpenStreetMap contributors"를 크레딧에 넣는다 |
| 삼각형 예산 | 지도 전체 20만 이하, 토큰·액자·패널은 개당 3천 이하 |

## 5. 정확성 규칙
- 모든 숫자·사실에 태그를 붙인다.
  - **[확인]** `FACTS.md`나 출처로 확인한 값
  - **[추정]** 계산한 값. 근거 1줄을 붙인다
  - **[설정]** 연출용으로 정한 값
- `FACTS.md`의 [확인] 값은 그대로 쓴다. 모르는 것은 지어내지 말고 "확인 필요"로 남긴 뒤 사용자에게 묻는다.
- 자막에 들어갈 시간·버스 번호·정류장 이름은 `FACTS.md` 1장 그대로 쓴다.

## 6. 진행 방법
1. 처음 시작하면 `REGISTRY.md`를 요약해 보여준다. 방식별·우선순위별 개수와 상태를 보여준다.
2. 상태가 `대기`인 항목을 **우선순위 1 → 2 → 3** 순서로, 같은 우선순위 안에서는 표 위쪽부터 하나씩 진행한다.
3. 방식별로 할 일:
   - **3D:** 4-1의 역할 분담대로 한다. ChatGPT는 `SPEC_TEMPLATE.md` 설계도와 참고 이미지(MAP04~06) 또는 연출 의도 문서(MAP07~08)까지만 만들고 멈춘다
   - **실제 사진:** `PHOTO_SHEET_TEMPLATE.md` 양식으로 필요한 컷, 후보 사진 2~3장(출처·라이선스·확인 결과), 선택 이유, 편집 기록, 영상 배치 작성. 사진 파일은 2-7 규칙대로 저장
   - **일러스트:** `IMAGE_SHEET_TEMPLATE.md` 양식으로 용도, 프롬프트, 결과 파일 작성
4. 항목 하나를 끝내면 멈추고, 결과 요약과 사용자가 확인할 점을 보여준 뒤 다음 명령을 기다린다.
5. 5개마다 8장의 검수를 하자고 제안한다.

### 사용자 명령어
| 사용자가 쓰는 말 | 할 일 |
|---|---|
| `다음` | 다음 `대기` 항목 진행 |
| `{ID}` 또는 `{ID} 해줘` | 그 항목으로 바로 이동 |
| `수정: 내용` | 직전 항목을 고치고 버전을 올려 다시 저장 |
| 사진 첨부 + `내 사진` | 사용자 본인 사진으로 등록(출처 = 사용자 촬영) |
| `수익화 안 함` | 상업적 이용 금지 라이선스도 후보에 포함 |
| `검수` | 8장 검수 실행 |
| `상태` | `REGISTRY.md` 진행 현황 요약 |
| `크레딧` | `CREDITS.md`로 엔딩 크레딧 문구 만들기 |

```
├─ INSTRUCTIONS.md · FACTS.md · REGISTRY.md · CREDITS.md · CHANGELOG.md
├─ templates/                       ← 고치지 않음
├─ assets/{ID}_{영문명}/             ← 3D: spec.md·images/(ChatGPT), 스크립트·.blend·.glb·previews/·validation.md(Claude)
│                                     (v1 초안 폴더도 여기 있음 — 보관용, 고치지 않음)
├─ photos/{ID}_{영문명}/             ← 실제 사진: photo_sheet.md, 원본 사진, 편집본(있으면)
└─ images/{ID}_{영문명}/             ← 일러스트: image_sheet.md, 이미지 파일
```
- **사진 파일 이름:** `{ID}_{번호}_{짧은영문설명}_orig.jpg`, 편집본은 `..._edit.jpg` 예) `PH20_01_daritdol_ushape_orig.jpg`
- **저장할 때마다 할 일:**
  1. 해당 기록 파일의 버전과 Changelog를 갱신한다.
  2. `REGISTRY.md`의 `상태`(대기 → 초안 → 검토 → 확정)와 `버전`을 바꾼다.
  3. 사진·자료를 썼으면 `CREDITS.md`에 추가한다.
  4. `CHANGELOG.md` 맨 위에 한 줄 추가한다.
- **커밋:**
  - 이 지시서가 있는 브랜치에 커밋한다. 바로 쓸 수 없으면 새 브랜치 + Pull Request로 올린다.
  - 항목 1개 = 커밋 1개. 메시지 예: `photo(PH20): 다릿돌전망대 사진 기록 v1.0` / `design(MAP04): 탈것 토큰 설계도 v1.0`(ChatGPT) / `3d(MAP04): 탈것 토큰 모델 v1.0`(Claude) / `illust(IL01): 여행자 캐릭터 v1.0`
- **저장소에 직접 쓸 수 없을 때:** 저장할 파일마다 경로를 제목으로 하고 전체 내용을 코드 블록으로 출력한다. 생략하지 않는다. 사진은 출처 링크만 적고 사용자가 내려받게 한다.

## 8. 검수 (`검수` 명령)
1. **사진 출처 감사:** 모든 사진의 라이선스, 상업적 이용 가능 여부, 변경 금지 여부, 출처 표기 문구, 확인 4단계(2-5) 결과. 빠진 항목은 빨간 줄로 표시한다.
2. **편집 감사:** 사진마다 편집 기록이 2-4의 허용 범위 안인가.
3. **자막 감사:** 자막의 시간·버스 번호·장소 이름이 `FACTS.md`와 사진 내용에 맞는가.
4. **일러스트 감사:** 실제 장소·음식을 사실적으로 그린 일러스트가 없는가.
5. **3D 감사:** 설계도에 빠진 숫자가 없는가, Claude의 `validation.md`에 남은 문제가 있는가.

결과는 `busan-3d/REVIEW_{날짜}.md`로 저장한다.
