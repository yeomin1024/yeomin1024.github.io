# 작업 지시서: 부산 3D 여행 영상 오브젝트 설계도

버전: v1.0.0 — 2026-11-10 — 최초 작성

> **이 파일을 읽는 AI(ChatGPT 등)에게**
> 이 파일과 아래 "먼저 읽을 파일"이 이 작업의 규칙이다. 대화에서 사용자가 다르게 말하면 사용자의 말을 따른다.
> 이 폴더(`busan-3d/`) 밖의 파일은 읽거나 고치지 않는다. 이 저장소는 블로그이기도 하다.

## 1. 역할과 목표
- 너는 3D 애니메이션 제작팀의 리드 3D 아티스트이자 테크니컬 아티스트다.
- 목표는 오브젝트마다 **설계도(모델링 사양서)**를 만드는 것이다. 모델러가 추가 질문 없이 Blender에서 바로 만들 수 있어야 한다.
- 오브젝트 하나마다 아래 4가지를 만든다.
  1. 설계도
  2. 블록아웃 스크립트: 실행하면 실제 치수의 기본 형태가 생기는 Blender 스크립트
  3. 참고 이미지 프롬프트
  4. (이미지를 만들 수 있으면) 참고 이미지

## 2. 영상·스타일·툴
- **영상:** 여행자 2명이 KTX로 부산역에 도착해 택시 없이 버스만 타고 2박 3일 부산을 여행하는 3D 애니메이션이다. 줄거리는 `FACTS.md` 1장에 있다.
- **화면:** 16:9, 1920×1080(최종 3840×2160), 24fps, 3~5분, 11월 배경.
- **스타일:** 스타일라이즈드 미니어처 디오라마. 부드러운 모서리, 단순화한 형태, 단순한 PBR 재질. 실루엣은 실제와 닮게 하고 디테일은 절제한다.
- **툴:** Blender 4.2 LTS 이상, 렌더는 Eevee 또는 Cycles. 납품은 `.blend`와 `.glb`(LOD0).

## 3. 기술 규칙
| 항목 | 규칙 |
|---|---|
| 단위 | 1 Blender unit = 1 m. 소품은 mm 병기 |
| 축 | Z가 위. 오브젝트 정면은 -Y 방향(Blender Front 뷰에 보이는 면) |
| 원점 | 에셋 원점은 바닥 중앙(0,0,0). 회전·개폐 부품은 실제 회전축에 원점 |
| 트랜스폼 | 납품 시 스케일 1, 회전 0 (Apply 완료) |
| 오브젝트 이름 | `{ID}_{영문명}_{부품}_{LOD}` 예) `VEH02_CityBus_DoorFront_L0` |
| 재질 이름 | `M_{영문명}_{재질}` 예) `M_CityBus_Paint` |
| 텍스처 이름 | `T_{영문명}_{BaseColor\|Normal\|ORM\|Emission}` |
| 삼각형 예산 | 클로즈업(H) 2만~8만 / 중간(M) 5천~2만 / 배경(B) 300~5천 / 군중 300 이하 / 키트 모듈 개당 500~3천 |
| 텍셀 밀도 | H 1024px/m, M 512px/m, B 256px/m. 반복 표면은 트림시트·타일 텍스처 우선 |
| 스케일 기준 | 성인 1.70 m. 모든 설계도에 사람 대비 비율을 적는다 |
| 기준 치수 (추정할 때) | 문 높이 2.1 m, 계단 한 칸 높이 0.17 m·깊이 0.30 m, 차로 폭 3.25 m, 건물 층고 2.7~3.0 m, 앉은 사람 키 약 1.3 m |

## 4. 정확성 규칙 (가장 중요)
- 모든 숫자 옆에 근거 태그를 붙인다.
  - **[확인]** `FACTS.md`의 값이나 공식 자료. 출처를 적는다.
  - **[추정]** 사진 비율이나 기준 치수로 계산한 값. 계산 근거를 1줄 적는다.
  - **[설정]** 연출을 위해 임의로 정한 값.
- `FACTS.md`의 [확인] 값은 그대로 쓴다. 바꾸려면 근거를 대고 사용자에게 먼저 묻는다.
- 모르는 실측값을 사실처럼 쓰지 않는다. 확실하지 않으면 설계도 13번 섹션에 올리고, 필요한 사진(대상·각도)을 요청한다.
- 사용자가 사진을 주면 그 사진을 근거로 [추정] 값을 다시 계산하고 버전을 올린다.

## 5. 저작권·상표
- 실제 로고, 상표, 가게 간판 글씨, 앱 화면, 캐릭터 조형물은 따라 만들지 않는다. 예를 들어 감천문화마을 어린왕자 조형물, 코레일 로고, 지도 앱 화면이 그렇다.
- 이런 것은 가상 브랜드명과 일반화된 디자인으로 바꾸고 대체안을 적는다.
- 건축물·교통수단은 알아볼 수 있는 실루엣까지만 재현한다.
- 버스 노선 번호와 정류장 이름은 그대로 써도 된다.

## 7. 진행 방법
1. 처음 시작하면 `REGISTRY.md` 표를 요약해서 보여준다. 전체 개수, 등급별 개수, 상태별 개수를 보여준다.
2. 상태가 `대기`인 오브젝트를 **우선순위 1 → 2 → 3** 순서로, 같은 우선순위 안에서는 표 순서대로 하나씩 진행한다.
3. 오브젝트마다 할 일:
   1. `SPEC_TEMPLATE.md` 양식대로 설계도를 쓴다. 섹션 번호와 제목은 바꾸지 않는다.
   2. `blockout_template.py`를 복사해 `1. 에셋 정보`, `2. 재질`, `3. 부품` 블록만 설계도 값으로 채운다. 아래쪽 공용 함수는 고치지 않는다.
   3. 참고 이미지 프롬프트를 영어로 쓴다(양식 12번).
   4. 9장의 규칙대로 저장하고 `REGISTRY.md` 상태를 바꾼다.
4. 오브젝트 하나를 끝내면 멈추고, 결과 요약과 확실하지 않은 값 목록을 보여준 뒤 사용자의 다음 명령을 기다린다.
5. 오브젝트 5개마다 10장의 검수를 하자고 제안한다.

### 사용자 명령어
| 사용자가 쓰는 말 | 할 일 |
|---|---|
| `다음` | 다음 `대기` 오브젝트 진행 |
| `{ID}` 또는 `{ID} 해줘` | 그 오브젝트로 바로 이동 |
| `수정: 내용` | 직전 오브젝트를 고치고 버전을 올린 뒤(예: v1.0 → v1.1) 다시 저장 |
| 사진 첨부 + `보정` | 사진 근거로 [추정] 값을 재계산하고 버전 올림 |
| `이미지` | 12번 프롬프트로 참고 이미지 생성 후 `images/`에 저장 |
| `검수` | 10장 검수 실행 |
| `상태` | `REGISTRY.md` 진행 현황 요약 |

## 8. 오브젝트 종류별 추가 섹션
설계도 양식 뒤에 아래 섹션을 덧붙인다.

- **키트(분류가 키트인 것: 감천 주택, 시장 골목, 해안 데크, 레일 등)**
  - K1 그리드: 스냅 단위, 층고, 모듈 폭 종류
  - K2 모듈 목록: ID, 치수, 연결 면, 변형 수
  - K3 조합 규칙: 금지 조합, 팔레트 색 배분 비율(%), 반복이 티 나지 않게 하는 규칙(회전·색·소품 랜덤 범위)
  - K4 배치 자동화: Geometry Nodes 또는 Python 랜덤 배치. **랜덤 시드 고정, 시드 값 기록**
  - K5 화면 크기별(소·중·대) 예시 배치 3종의 오브젝트 수·삼각형 합계
- **캐릭터**
  - C1 비례: 등신, 키, 어깨 폭, 손 크기(교통카드·스마트폰을 쥘 수 있는지)
  - C2 의상 레이어와 분리 메시 여부
  - C3 관절·얼굴 엣지 루프
  - C4 리그: Rigify 기준, 손·등에 소품 붙이는 위치
  - C5 표정 셰이프키 8종
  - C6 동작 클립 목록(이름, 프레임 수@24fps, 루프 여부, 사용 장면)
  - C7 T-포즈 정면·측면·배면 턴어라운드 이미지 프롬프트
- **음식**
  - F1 그릇·식기 실측(mm)과 재질
  - F2 위에서 본 배치도(ASCII)와 고명 개수·위치
  - F3 셰이딩 수치: 국물 IOR 1.33·기름막, 면·회 SSS, 구이 광택
  - F4 김 파티클(양·속도), 젓가락으로 집을 때 분리할 부품
  - F5 45° 카메라 권장 초점거리
- **효과·설정(분류가 FX인 것)**: 3D 모델이 아니다. 설계도 양식 대신 셰이더 노드 구성, 수치, 시간대별 프리셋 표로 쓴다.

## 9. 결과물 저장 규칙 (저장소에 올리기)
### 폴더 구조
```
busan-3d/
├─ INSTRUCTIONS.md      ← 이 파일 (고치지 않음)
├─ FACTS.md             ← 사실 자료 (새로 확인한 사실은 사용자 확인 후 추가)
├─ REGISTRY.md          ← 진행 상태 (오브젝트마다 갱신)
├─ CHANGELOG.md         ← 작업 기록 (오브젝트마다 한 줄 추가)
├─ templates/           ← 양식 (고치지 않음)
└─ assets/
   └─ {ID}_{영문명}/     예) VEH02_CityBus/
      ├─ spec.md                 설계도
      ├─ blockout.py             블록아웃 스크립트
      ├─ reference_prompt.txt    참고 이미지 프롬프트(영어)
      └─ images/                 참고 이미지 (만들었을 때만)
```
- 폴더 이름은 `REGISTRY.md`의 `ID`와 `영문명` 열을 그대로 쓴다.

### 저장할 때마다 할 일
1. `spec.md` 맨 위 버전 줄과 맨 아래 Changelog를 갱신한다.
2. `blockout.py` 맨 위 `# VERSION:` 줄과 `SPEC_VERSION` 값을 설계도 버전과 맞춘다.
3. `REGISTRY.md`에서 그 줄의 `상태`(대기 → 초안 → 검토 → 확정)와 `버전`을 바꾼다.
4. `CHANGELOG.md` 맨 위에 한 줄 추가: `- 2026-MM-DD | VEH02 | v1.0 | 설계도·스크립트 최초 작성`
5. 커밋한다.

### 커밋 규칙
- **브랜치:** 이 지시서가 있는 브랜치에 커밋한다. 그 브랜치에 바로 쓸 수 없으면 새 브랜치를 만들고 Pull Request를 연다.
- **커밋 단위:** 오브젝트 1개 = 커밋 1개.
- **메시지 형식:** `asset(VEH02): 시내버스 설계도 v1.0` / 수정은 `asset(VEH02): v1.1 — 버스 높이 사진 기준 보정`
- `busan-3d/` 밖의 파일은 만들거나 고치지 않는다.

### 저장소에 직접 쓸 수 없을 때
저장소 쓰기 권한이나 도구가 없으면, 위 경로마다 **파일 경로를 제목으로 하고 파일 전체 내용을 코드 블록으로** 출력한다. 사용자가 그대로 복사해 올릴 수 있게 하고, 일부만 출력하거나 "생략" 표시를 넣지 않는다.

## 10. 검수 (`검수` 명령)
지금까지 `초안` 이상인 설계도 전체를 대상으로 표를 만든다.
1. **스케일 매트릭스:** 모든 에셋의 높이와 사람(1.7 m) 대비 비율. 같은 화면에 나오는 에셋끼리 맞지 않는 곳도 찾는다(예: 버스 문 높이 vs 정류장 지붕 높이).
2. **미확정 값:** [추정]·[설정] 값 목록과 확정 우선순위.
3. **규칙 위반:** 팔레트, 이름 규칙, 삼각형 예산을 어긴 곳.
4. **씬 매트릭스:** 행=장면, 열=에셋 ID. 장면별 삼각형 합계.
5. **재사용 기회:** 합칠 수 있는 재질과 모듈.

결과는 `busan-3d/REVIEW_{날짜}.md`로 저장하고, 고쳐야 할 설계도는 새 버전 번호와 바뀐 점까지 적는다.
